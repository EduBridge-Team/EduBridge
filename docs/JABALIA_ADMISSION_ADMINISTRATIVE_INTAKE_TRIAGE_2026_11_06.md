# جباليا: متابعة تجهيز طلب الالتحاق دون قرار قبول

**التاريخ:** 2026-11-06
**الحالة:** تنفيذ مسار متابعة إداري محصور وصريح؛ **ليس** مراجعة مرشد أو قبولًا أو رفضًا طبيًا

## الوظائف المنفذة

- جدول جديد: jabalia_admission_intake_events يحفظ أحداثًا إدارية ملحقة، بمعرف المؤسسة والمدرسة والطالب والطلب وإصدار الطلب والحالة والحساب ودوره الإداري ووقت الإجراء. لا توجد ملفات أو أسماء أو أسباب أو تشخيصات أو نصوص طبية في السجل.
- GET/POST /api/school/jabalia/enrollment-requests/{enrollmentRequest}/intake-triage؛ يتطلب مدير مدرسة مُعيّنًا **بحسابه الشخصي** أو نائب مدير مفوّضًا بصلاحية enrollment على المدرسة **نفسها**. لا يحصل الحساب الرسمي للمدرسة أو أولياء الأمور على هذه الصلاحية.
- الحالات الإدارية فقط:
  - evidence_followup_needed: استكمال أنواع المستندات.
  - awaiting_counselor_assignment: انتظار تحديد المرشد المسؤول، **ولا يعني أن مرشدًا أُسند بالفعل**.
  - administrative_followup_needed: متابعة إدارية داخلية.
- تُعرض أحدث حالة وسجل العمليات (20 حدثًا/صفحة)، وتُضاف الأحداث دون تعديل التاريخ السابق.
- يمنع التعديل على طلب منتهي، ويشترط expected_request_version وexpected_event_id لمنع الحفظ الصامت عندما يعدل ولي الأمر الطلب أو يقوم مسؤول آخر بتغيير حالة التجهيز. تُرفض الحالات المتطابقة أو المتقادمة بـ409.
- واجهة React داخل قائمة جاهزية الالتحاق محمّلة **عند الطلب**؛ لا تُظهر ملفات طبية أو تُنتج موافقة.
- **تصحيح أمني مهم:** لم يعد مسار القرار العام يسمح لطلبات جباليا بالرفض النهائي دون مراجعة المرشد، كما كان يمنع القبول. ويُزال زر الرفض النهائي من واجهة طلبات جباليا. مسارات المدارس الأخرى تحتفظ بالسلوك السابق.
- لا تُغيّر هذه الخطوة حالة school_enrollment_requests.status أو version أو قيد الطالب في student_enrollments، ولا تتيح رفع المستندات الطبية أو تسليمها لمرشد.

## حدود الموافقة المطلوبة

**لا** تفوّض هذه الحالات مرشدًا، ولا تصدر تقريرًا سريريًا، ولا تقرر قبولًا أو رفضًا، ولا تثبت صحة تقرير السمع. لا تُفتح الموافقة النهائية بمجرد تحويل حالة التجهيز إلى «انتظار تعيين مرشد». لا تتحقق خطة القبول الكاملة حتى تعتمد الجمعية صراحةً:

1. من هو المرشد وما آلية إنشاء هويته وتكليفه لكل طلب، وكيف تُلغى صلاحياته.
2. الوثائق المسموح للمرشد بمراجعتها، وسياسة الموافقة والخصوصية والاحتفاظ.
3. فصل توقيع المرشد عن قرار المدير/النائب، ومتى يُسمح بالرفض بعد المراجعة.
4. النماذج المعتمدة وسجل التدقيق وقواعد إشعار ولي الأمر وحقوقه في التصحيح.
5. النسخ الاحتياطي المجرب واستعادة الملفات المشفرة واختبار الأدوار.

## الجودة والنشر

- اختبارات Laravel: صلاحية مدير المدرسة ونائب مفوض، رفض المدير المنتهي تعيينه والنائب دون enrollment وحساب المدرسة والجهات الخارجية، تاريخ الأحداث، منع الحالات غير المسموحة، تعارض نسخة الطلب/آخر حدث، وعدم تغيير قرار القبول أو إرسال إشعارات.
- اختبار React: التشغيل عند الطلب ومطابقة المدرسة والطلب، عدم عرض إجراءات الموافقة أو الرفض لجباليا.
- الترحيل الإضافي 2026_11_06_060000_create_jabalia_admission_intake_events.php يجب تطبيقه على **قاعدة بيانات جباليا المنعزلة قبل تشغيل API الجديد**. عند غياب الجدول، يفشل مسار التجهيز الجديد بالرمز 503 ولا يتجاوز السجل.
- قبل النشر: نسخ احتياطية حديثة ومتحقق منها للـPostgreSQL وملفات المعلمين وقبول الطلاب، مع تجربة استعادة منفصلة. لا تشغّل migrate:fresh أو institutions:provision-jabalia على البيئة الحالية.
- بعد النشر: التحقق من SHA المنشور، صحة الحاويات، HTTP 200، وتجربة تحقق صحيحة وأخرى مرفوضة بحسابات اصطناعية في جباليا؛ عدم اختبار مستندات طبية حقيقية من دون موافقة الجمعية.
